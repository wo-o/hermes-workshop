# GitHub 이슈 명세 작성

짧은 요청을 재현 가능하고 완료 여부를 판단할 수 있는 이슈로 구조화합니다. 확인하지 않은 파일이나 심볼을 만들지 않습니다.

## 사용 시점
- 버그 또는 기능 요청을 GitHub 이슈로 정리할 때
- 구현 전에 완료 조건과 테스트 범위를 합의할 때
- 단순 메모에는 사용하지 않습니다.

## 절차
1. 저장소가 주어지면 GitHub 도구 또는 checkout에서 README, 관련 코드, 기존 이슈를 읽습니다.
2. 요청을 문제, 사용자 영향, 현재 동작, 기대 동작으로 분리합니다.
3. 버그라면 최소 재현 절차와 관찰된 결과를 작성합니다.
4. 기능이라면 포함 범위와 제외 범위를 명시합니다.
5. 객관적으로 확인 가능한 완료 조건을 체크박스로 작성합니다.
6. 필요한 단위, 통합, 수동 검증을 구분합니다.
7. 로그와 예제에서 민감정보를 제거합니다.
8. 생성 요청이면 초안을 먼저 보여주고 승인 후 GitHub 쓰기 도구를 호출합니다.
9. 생성 후 이슈 URL을 다시 조회해 제목과 본문을 확인합니다.

## 출력 형식
```text
제목:
## 배경
## 현재 동작
## 기대 동작
## 재현 절차
## 완료 조건
## 테스트
## 범위 제외
```
적용되지 않는 섹션에는 `해당 없음` 또는 `확인 필요`를 사용합니다.

## 주의 사항
- 초안만 요청했다면 GitHub에 생성하지 않습니다.
- 검증할 수 없는 완료 조건을 사용하지 않습니다.
- 코드 확인 없이 파일명, 함수명, 담당자를 지어내지 않습니다.

## 검증
- 제목에 문제 또는 기대 결과가 드러납니다.
- 각 완료 조건을 테스트나 관찰로 판정할 수 있습니다.
- 실제 생성했다면 이슈 URL을 재조회했습니다.
