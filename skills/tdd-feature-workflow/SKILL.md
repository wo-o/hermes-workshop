# 테스트 주도 기능 구현

요구사항을 테스트로 먼저 표현한 뒤 최소 구현을 추가합니다. 기존 테스트 방식과 프로젝트 관례를 우선합니다.

## 사용 시점
- 입력과 기대 결과가 분명한 작은 기능을 구현할 때
- 회귀 위험이 있는 동작을 변경할 때
- 요구사항이 불명확한 탐색 작업에는 바로 적용하지 않습니다.

## 절차
1. `search_files`와 `read_file`로 구현 위치, 기존 테스트, 매니페스트를 확인합니다.
2. 요구사항을 정상 입력, 경계값, 잘못된 입력 사례로 바꿉니다.
3. 가장 작은 사례 하나를 기존 테스트 스타일로 작성합니다.
4. 해당 테스트를 실행해 구현 부재 때문에 실패하는지 확인합니다.
5. 테스트를 통과시키는 최소 구현을 `patch`로 적용합니다.
6. 같은 테스트를 다시 실행해 GREEN을 확인합니다.
7. 다음 경계 사례에 대해 RED → GREEN을 반복합니다.
8. 모든 테스트가 녹색일 때만 중복과 이름을 정리합니다.
9. 관련 테스트 전체와 lint 또는 type check를 실행합니다.

## 완료 보고
```text
RED: <실패한 테스트와 핵심 오류>
GREEN: <통과한 테스트>
REFACTOR: <수행한 정리 또는 없음>
```

## 주의 사항
- 구현과 테스트를 동시에 작성해 RED 확인을 생략하지 않습니다.
- 내부 호출보다 사용자에게 보이는 결과를 검증합니다.
- 테스트를 통과시키려고 요구사항이나 기대값을 바꾸지 않습니다.

## 검증
- 최소 한 개 테스트가 구현 전 실패하고 구현 후 통과했습니다.
- 요구사항에 필요한 경계 사례가 포함되었습니다.
- 관련 테스트 전체가 통과했습니다.
