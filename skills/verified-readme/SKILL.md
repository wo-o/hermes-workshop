# 검증된 README 작성

처음 방문한 사용자가 실제로 실행하고 결과를 확인할 수 있는 README를 만듭니다. 문서 명령은 프로젝트와 현재 환경에서 근거를 확인합니다.

## 사용 시점
- 새 프로젝트의 README를 작성할 때
- 오래된 설치 또는 실행 가이드를 갱신할 때
- 문장 교정만 요청받았다면 검증 범위를 넓히지 않습니다.

## 절차
1. `read_file`로 기존 README, 매니페스트, 환경변수 예제, 자동화 파일을 확인합니다.
2. `search_files`로 실행 진입점과 문서 명령을 추적합니다.
3. 대상 독자와 가장 짧은 성공 경로를 정합니다.
4. 요구 사항 → 설치 → 실행 → 검증 → 문제 해결 → 정리 순서로 구성합니다.
5. 명령을 `terminal`로 실행하거나 공식 CLI help에서 구문을 확인합니다.
6. 실행 성공과 서비스 준비 상태를 구분해 health check 또는 예상 출력을 추가합니다.
7. 환경변수 이름과 용도만 설명하고 실제 secret 값은 기록하지 않습니다.
8. 문제 해결에는 증상, 원인, 확인 명령, 해결책을 연결합니다.
9. 링크, 코드 펜스, 절대 경로, 비밀 값을 검사합니다.

## 최소 구조
```text
# 프로젝트 이름
## 요구 사항
## 설치
## 실행
## 검증
## 문제 해결
## 정리
## 보안
```

## 주의 사항
- 확인하지 않은 의존성이나 명령을 만들지 않습니다.
- 요청 수락과 비동기 작업 완료를 같은 성공으로 표현하지 않습니다.
- 로컬 무인증 설정을 외부에 노출하도록 안내하지 않습니다.

## 검증
- 새 사용자가 최소 성공 결과를 확인할 수 있습니다.
- 필수 명령이 실제 프로젝트 또는 공식 help와 일치합니다.
- secret, 로컬 절대 경로, 깨진 링크가 없습니다.
