# 체계적인 버그 수정

증상을 보고 즉시 코드를 바꾸지 않고 재현, 원인 규명, 회귀 테스트 순서로 수정합니다.

## 사용 시점
- 오류, 간헐적 실패, 잘못된 결과를 조사할 때
- 원인 분석과 코드 수정을 함께 요청받았을 때
- 새 기능 구현이나 단순 코드 설명에는 사용하지 않습니다.

## 절차
1. `search_files`와 `read_file`로 오류 메시지, 관련 심볼의 정의·사용처·테스트를 찾습니다.
2. `terminal`의 `git status --short`로 기존 작업을 확인합니다.
3. 가장 작은 재현 명령을 실행하고 실제 오류와 입력을 기록합니다.
4. 증상과 원인 가설을 분리하고 각 가설의 확인 방법을 정합니다.
5. 최초로 잘못된 값이 만들어진 지점을 찾습니다.
6. 수정 전에 회귀 테스트를 추가하고 실패를 확인합니다.
7. 근본 원인을 해결하는 최소 변경만 `patch`로 적용합니다.
8. 회귀 테스트, 관련 테스트, 품질 검사를 실행합니다.
9. 같은 결함이 가능한 형제 호출 경로도 검색합니다.

## 완료 보고
```text
원인: <실행 시점·주체·잘못된 동작>
수정: <최소 변경>
검증: <실행한 명령과 실제 결과>
남은 위험: <없음 또는 구체적 제한>
```

## 주의 사항
- 재현하지 못했다면 추정 수정을 완료라고 보고하지 않습니다.
- 예외를 숨기거나 테스트 기대값만 바꾸지 않습니다.
- 기존 미커밋 변경을 되돌리지 않습니다.

## 검증
- 수정 전 회귀 테스트가 같은 증상으로 실패했습니다.
- 수정 후 회귀 테스트와 관련 테스트가 통과했습니다.
- 완료 보고의 원인이 실제 실행 결과와 연결됩니다.
